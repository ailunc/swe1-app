# Polls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify the tutorial polls app, then publish the repository and deploy in the student's AWS account when account access permits.

**Architecture:** A Django project (`mysite`) and app (`polls`), with server-rendered templates and the tutorial's final generic views. SQLite for local development; PostgreSQL for persistent cloud storage. Elastic Beanstalk serves the WSGI app and WhiteNoise serves collected static assets.

**Tech Stack:** Python 3.13, Django 5.2, PostgreSQL, WhiteNoise, Elastic Beanstalk.

**Spec:** `docs/superpowers/specs/2026-10-12-polls-design.md`

## Global Constraints

- Complete Django 5.2 tutorial Parts 1–4, including the final generic views.
- Personal GitHub repository name: `swe1-app`.
- Keep credentials and local environments out of Git.
- Do not invent personal information, author declarations, or a history of work.
- Verify the actual public URL before declaring deployment complete.

## Review Focus

- A choice from another question must not receive a vote (Task 1).
- A GET to the vote endpoint must not change the database (Task 1).
- A missing CSRF token must reject a POST (Task 1).
- Re-running seed data must not reset votes or duplicate choices (Task 2).
- Missing production secrets must fail startup rather than fall back to a public key (Task 2).
